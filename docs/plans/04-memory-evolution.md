# 第 4 期：记忆进化——更像人脑

目标：在第 3 期星图（提取/检索/注入已跑通）基础上，把记忆系统从"档案柜"升级成"活的记忆"：会巩固、会遗忘、可溯源、能联想、按意思找。

2026-07-12 与泽敲定，五个方向都做，按下面顺序分期。排序原则：收益大、改动小的先上；向量最重，放最后。

## 现状盘点（第 3 期遗留）

- 已有：fragments/entities/episodes/links 四表 + FTS5 trigram；scribe 提取（haiku）；librarian 检索注入（权限分级【可引用/需谨慎/仅联想】、read_count 抑制、静默地板、实体名扫描）；星图前端
- episodes 表建了但没人往里写（合并逻辑没做）
- links 表在记权重，检索时没用上（只用于星图显示）
- 03 计划 P4 占位的"碎片合并/概述重写/衰减/去重/向量"全部并入本期

## P1 做梦（夜间巩固）——先做，收益最大

人脑睡眠时巩固记忆：当天的过一遍，重复的合并，矛盾的修正，零散的升华成叙事。

- `server/memory/dreamer.ts`：每晚低峰时段（比如 04:00）定时跑一次，haiku 驱动
- 干四件事：
  1. **对账**：当天新碎片 vs 既有碎片，同一事实的旧版本标 `superseded`（加 status 值，不删行，保留演变史）；矛盾的以新为准
  2. **去重合并**：字面不同、说的是同一件事的碎片合成一条
  3. **升华**：同一实体下攒够 5+ 条相关碎片，合写成一条 episode（100~250 字叙事），原碎片标 `consolidated`——episodes 表从此有人写了
  4. **实体概述重写**：本期动过的实体，重写 overview
- 成本控制（Pro 额度紧）：只处理当天有新碎片的实体；当天没新碎片整个不跑；单次处理量设上限，处理不完的顺延到明晚
- 失败安全：任何一步挂掉记日志跳过，绝不动已有数据；所有改动先写后验（改完 count 对不上就回滚）
- 跑完在日志里留一行"梦境报告"：合并了几条、升华了几条、修正了几条

## P2 温度（遗忘与变牢）

人的记忆不是平权的：常被提起的越来越牢，久不碰的淡出但不消失。

- fragments 加 `heat REAL DEFAULT 1.0` 列
- 升温：被 librarian 注入且泽当轮确认/回应 +0.3；做梦时被引用进 episode +0.2
- 降温：做梦时统一乘衰减系数（比如 0.98/天），有下限（0.1），**降到底也不删**——存档里永远有原文
- librarian 打分公式加入热度因子；现有 read_count 抑制保留（它防"一条碎片霸屏"，热度管"这条记忆还活着吗"，方向互补）
- 权限分级从纯按年龄改成年龄 × 热度：一条三个月前但常被提起的记忆，仍然可以【可引用】

## P3 出处可溯（碎片链回原文）

泽要的是可核查的真。碎片是二手提炼，链回原话才是铁证。

- fragments 已有 `session_id`，补 `msg_index` 列（提取时记下来源消息位置）；存量碎片没有就留空，不回填
- 注入格式带溯源脚注，麦穗引用记忆时可以当场用 read_history 调原文验证
- 星图前端：点碎片 → 跳转到翻历史工具的对应会话位置（前端已有历史查询页，加个锚点跳转）

## P4 联想（图检索）

人想起事情是被牵出来的——现在 links 表记了实体关联权重，只用来画星图，浪费。

- librarian 实体扫描命中实体 A 后，沿 links 找权重最高的 1~2 个邻居实体，把它们的高热碎片也拉进候选（降权计分，比直接命中低）
- 效果：泽提"妈妈"，"赖皮"（如果常一起出现）的相关碎片也可能浮上来
- 上限控制：联想来的碎片最多占注入条数的 1/3，静默地板照旧——联想是佐料不是主菜

## P5 向量双路（按意思找）

当初留的口子（2026-07-04 说好的），现在填。**双路并跑取并集，不是替换**：关键词管精确（人名、梗词如"嬷嬷"），向量管模糊（"上次我 emo 那回"→"泽掉眼泪"）。

- 向量库：`sqlite-vec`（SQLite 扩展，不引新服务，跟现有 memory.db 一个文件体系）
- 嵌入模型二选一，实施时按额度和延迟实测定：
  - API：走已配通道的嵌入接口（每条碎片 + 每次查询都要算，持续成本）
  - 本地：中文小模型（bge-small-zh 级别，onnx 跑），一次下载零边际成本，但服务器 CPU 得扛得住
- 入库：做梦时批量算新碎片向量（蹭夜间任务，不拖累聊天时延）
- 检索：FTS 命中 + 向量 top-k 取并集去重，分数归一后走既有打分管线
- 先写个 20 条测试集（字面不同意思同的查询对）验收召回，达标再全量开

## 验收标准

- P1：连聊三天后查 memory.db，能看到 superseded/consolidated 状态流转和非空 episodes；梦境报告日志正常
- P2：常聊的记忆热度可见地高于冷记忆；三个月前的高热记忆仍以【可引用】注入
- P3：任一新碎片能从星图点回原始会话原文
- P4：提到实体 A 时，强关联实体 B 的碎片出现在注入里且不超过 1/3 配额
- P5：测试集里"字不同意思同"的查询召回率明显高于纯 FTS；聊天时延无感知增加
- 全程：聊天主流程零阻塞——做梦、算向量全部夜间异步；任何记忆子系统挂掉聊天照常
