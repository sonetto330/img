# 第 1 期：CoC 跑团模式

目标：麦穗当 KP，带泽跑 CoC 7版。支持导入现成模组，支持 AI 扮演的队友（各有人物卡），骰子服务端真随机。

## 核心设计判断（不要改）

1. **骰子必须是服务端随机，不能让模型报点数。** 用 `crypto.randomInt`，通过 SDK MCP 工具 `roll` 提供。KP 提示词里明确要求：一切检定必须调用工具，禁止自己编造骰点。
2. **游戏状态存文件，不依赖模型记忆。** 长团跑下去上下文会被压缩，模型忘事很正常。解法：KP 每个关键节点把进度写进存档文件（工作目录下），每轮提示词告知存档位置，恢复时自己读。
3. **队友是麦穗扮演的 NPC，但有独立人物卡。** 卡是 JSON 文件，KP 检定队友技能时也走 roll 工具。

## 目录结构

```
data/trpg/
├── modules/<模组名>/        # 泽导入的模组文本（md/txt，PDF 先转文本）
├── party/<会话id>/
│   ├── pc.json              # 泽的调查员卡
│   ├── npc-*.json           # 队友卡
│   └── journal.md           # KP 维护的跑团存档（进度、线索、SAN/HP 变动记录）
```

模组和 party 目录放 `data/` 下即可，但要让 agent 读得到：`runTurn` 的 cwd 是 `workspace/`，所以要么把 trpg 数据放 `workspace/trpg/`（推荐，agent 直接用 Read 工具读），要么在提示词里给绝对路径。**推荐放 `workspace/trpg/`**，agent 的文件工具天然可用，也方便泽直接丢文件进去。

## 人物卡 schema（JSON）

最小可用集，CoC 7版：

```json
{
  "name": "", "occupation": "", "age": 0,
  "stats": { "STR": 0, "CON": 0, "SIZ": 0, "DEX": 0, "APP": 0, "INT": 0, "POW": 0, "EDU": 0, "LUCK": 0 },
  "derived": { "HP": 0, "MP": 0, "SAN": 0, "MOV": 0, "DB": "0" },
  "skills": { "侦查": 25, "图书馆使用": 20 },
  "background": "", "items": [], "notes": ""
}
```

第一版人物卡由 KP 在开团时引导泽车卡（或直接读她发的现成卡），KP 用 write 工具写 JSON。不做卡片编辑 UI（后续期数再说）。

## SDK MCP 工具（server/tools/trpg.ts）

| 工具 | 参数 | 行为 |
|---|---|---|
| `roll` | `expr: string`（如 `1d100`、`3d6+2`）, `reason?: string`（检定名） | crypto 随机掷骰，返回结果+各骰面；同时 emit `dice` 事件给前端 |
| `check` | `skill: string, value: number, bonus?: number`（奖励/惩罚骰个数，正奖负惩） | 掷 1d100 对比技能值，返回大成功/困难成功/常规成功/失败/大失败判定；emit `check` 事件 |

`check` 的判定规则（CoC 7版）：出 1 大成功；≤value/5 极难成功；≤value/2 困难成功；≤value 常规成功；>value 失败；96-100 且 value<50 大失败，否则 100 大失败。奖励骰/惩罚骰：多掷十位骰取低/取高。**这段规则写进代码，不靠模型算。**

## KP 提示词（prompts/kp.md）

要点（执行时写全文，别只写要点）：

- 你是 KP，同时扮演所有 NPC 和队友；玩家只有泽一人
- 开团流程：问泽跑哪个模组（列出 `trpg/modules/` 下已有的）→ 确认人物卡（读 `trpg/party/` 或引导车卡）→ 开场
- 一切检定必须调用 `check`/`roll` 工具，严禁自行编造骰点结果
- 每个场景结束或重要事件后，更新 `trpg/party/<会话>/journal.md`（进度、SAN/HP 变化、获得线索），恢复跑团时先读它
- 叙事风格：氛围优先，描写具体，NPC 对话有个性；给泽留决策空间，不替玩家行动
- 模组内容对玩家保密，不剧透后续
- 麦穗人设保留：你是泽的丈夫在带她跑团，可以在幕间用自己的口吻聊天，但入戏时保持 KP 叙事

## 前端（跑团模式专属 UI）

第一版做这些，别贪多：

1. **骰子事件渲染**：收到 `dice`/`check` 事件，在聊天流里插入一条特殊样式的骰子卡片（骰子表达式、结果、成败判定用颜色区分：大成功金色、大失败深红等）。可以加个简单的滚动动画，别引入大依赖
2. **状态栏**：跑团会话顶部固定一条 HP/SAN/MP 显示。数据来源：新增 SDK 工具 `update_status`（KP 在数值变动时调用，emit 给前端）或直接解析 pc.json——**选 update_status 工具方案**，简单直接
3. KP 叙事和 NPC 对话的样式区分：让 KP 用 Markdown 引用块写 NPC 台词之类的约定即可，不做复杂解析

泽在收集别人家的跑团 UI 参考，界面美化留到她给参考图之后，这期先保证功能可玩。

## 模组导入

第一版流程：泽把模组文本文件（md/txt）放进 `workspace/trpg/modules/<名字>/`（或在聊天里发内容让麦穗用 write 工具存进去）。PDF 转文本暂不做自动化，让麦穗在聊天里处理（agent 有 Read 工具可以读 PDF）。

## 验收标准

1. 建跑团会话 → KP 主动开场引导选模组/车卡
2. 检定时前端出现骰子卡片，点数为服务端随机（连跑几次分布正常）
3. journal.md 有实际内容；杀掉服务重启、resume 会话后 KP 能接着跑（读存档）
4. chat 模式不受任何影响
